Why Module 1 starts here

Before any algorithm, we need to understand the problem: a financial organisation wants better risk decisions from data, and needs the resulting system to be trustworthy. Module 1 answers "what do we build first?"

1. Ask the question

Are we predicting a number, a class, a group, or an unusual record? Each question points to a different family of techniques — this is the decision tree every concept below fits into.

2. Find the evidence

Income, debt, credit history are observations, not automatically "risk." Interpreting them is the whole job.

3. Choose the tool, not the trend

An algorithm is a tool for a specific question, not a trophy. This handbook always asks "why this, not something else?" before touching code.

Why this is the foundation for all 12 modules
Neural networks (Module 2) still need data. LLMs (Module 4) still need data and evaluation. Agents (Module 5) still depend on retrieval and permissions. Deployment (Module 10) still depends on a model whose training process is understood. Every later module inherits whatever quality — and whatever risk — Module 1 establishes here.

CONCEPT 1

NumPy

The numerical foundation almost everything else in this course sits on top of.

What it is

NumPy ("Numerical Python") is a library built around one core object — the ndarray — an n-dimensional grid of numbers of a single type, stored contiguously in memory and operated on by fast, compiled C code instead of the Python interpreter.

Why it exists — the history
1995 → 2005
Python's built-in list is flexible but slow for numeric work — every element is a full Python object with its own overhead, and looping over millions of them in pure Python is orders of magnitude slower than compiled code. Two competing array libraries emerged in the 1990s — Numeric and the more feature-rich but slower Numarray — splitting the scientific Python community. In 2005, Travis Oliphant merged their best ideas into NumPy, which has been the single standard ever since and now underlies pandas, scikit-learn, PyTorch and almost the entire Python data-science stack.
Alternatives — and why NumPy
OptionTrade-off
Plain Python lists + loopsNo installation needed, but 10–100× slower for numeric work at scale
Python's built-in array moduleFaster than lists but lacks vectorised math, broadcasting, and linear algebra
Write C/Fortran directlyFastest possible, but throws away Python's readability and ecosystem
NumPyC-speed vectorised math with Python's syntax — the practical middle ground the whole ecosystem standardised on

✓ Use it when

  • Data is numeric and homogeneous (all one type)
  • You need the same operation applied across thousands/millions of values
  • You're about to hand data to pandas, scikit-learn, or PyTorch — they all expect NumPy arrays underneath

✗ Reach for something else when

  • Data is labelled/tabular with mixed types — that's pandas (next lesson), built on top of NumPy
  • You need automatic differentiation for training a neural network — that's PyTorch's tensor, a NumPy-like object with gradients attached (Module 2)
REAL-WORLD FINANCIAL EXAMPLE
Computing debt-to-income for one customer is a single division. Computing it for 500,000 customers overnight, every night, as part of a batch risk report, is a NumPy vectorisation problem — the same formula, applied at scale, without writing a loop.
dti = monthly_debt / (annual_income / 12) — one line, works whether monthly_debt is a single number or an array of 500,000. Full walkthrough: Notebook, Lesson 1.

CONCEPT 2

Pandas + Exploratory Data Analysis

The table-manipulation layer, and the discipline of distrusting your data until it earns your trust.

What it is

Pandas gives Python a DataFrame — a labelled table, like a spreadsheet or a SQL result set, with named columns of mixed types. EDA is not a library at all — it's a process: summarise, visualise, question, and validate a dataset before trusting any model built on it.

Why it exists — the history
2008
Pandas was created by Wes McKinney while working at AQR Capital Management, a quantitative hedge fund — the motivating problem was literally financial time-series and panel data analysis in Python, because the alternative at the time was juggling R, Excel and hand-rolled NumPy code. Pandas' name itself comes from "panel data," an econometrics term. It is worth knowing that a financial institution's specific data-wrangling pain is the direct reason this tool exists.
Alternatives — and why pandas
OptionTrade-off
SQL directlyExcellent for querying, weaker for iterative, code-driven exploration and modelling hand-off
ExcelFast for small, manual exploration; does not scale, is not reproducible, is not version-controllable
R's data.frame / dplyrMature and elegant, but a separate language/ecosystem from the ML libraries you'll use next
Polars (newer)Often faster on large data via multi-threading and a Rust core; smaller ecosystem/community than pandas as of today
pandasThe default hand-off format to every ML library in this course

✓ Use it when

  • Data has named, mixed-type columns (numbers, categories, dates)
  • You need to filter, group, join or reshape before modelling
  • You need to inspect data quality before trusting it

✗ Reach for something else when

  • Data genuinely exceeds memory — that's a distributed-computing problem (Spark, Dask), out of scope for this course
  • You only need pure numeric array math — plain NumPy is lighter weight
The EDA discipline, not just the syntax
Before showing any model, ask: "if I were the data owner, what would I want to know about this table before letting an automated credit decision depend on it?" The notebook's Lessons 1–4 build this habit directly on the real RR Finance file: checking for missing values, duplicates, cross-field consistency (does employment_years fit inside this person's age?), and whether the target label itself behaves the way domain knowledge says it should.
REAL-WORLD FINANCIAL EXAMPLE
A bank's risk team receiving a new data feed from a partner institution runs exactly this kind of check before any model is allowed near it: row counts, null rates, duplicate customer IDs, and whether fields that should logically agree (like age and years employed) actually do.

CONCEPT 3

Feature Engineering

Translating financial reasoning into numbers a model can actually use.

What it is

Feature engineering is the practice of transforming raw fields into new inputs that better expose the pattern a model needs to learn — ratios, rates, counts, time differences — informed by domain knowledge, not by what's easiest to compute.

Why it exists — the history
Long before "machine learning" existed
This is not a 21st-century idea. Actuaries and economists have engineered ratios like debt-to-income and loan-to-value for over a century, because raw absolute numbers (₹30,000 of debt) are meaningless without context (relative to what income?). Classical statistics and econometrics were doing feature engineering long before it had that name — ML just inherited and formalised the practice.
Alternatives — and why we still hand-engineer here
OptionTrade-off
Manual, domain-informed features (this lesson)Interpretable, auditable, works well with small-to-medium tabular data and simple models
Automated feature engineering tools (e.g. Featuretools)Faster to generate many candidates, but can produce features nobody can explain to a regulator
Let a deep network learn its own features (Module 2)Neural networks can learn useful internal representations directly from raw inputs — this is exactly why Module 2 exists, and why hand engineering matters less (but doesn't disappear) once you add depth

✓ Do it when

  • Using classical models (regression, logistic regression, trees)
  • A domain expert can name the relationship that matters (e.g. "debt relative to income," not just "debt")

✗ Watch out for

  • Leakage: never build a feature from information that would only exist after the event you're predicting
  • Over-engineering redundant ratios that just re-encode the same signal multiple times
REAL-WORLD FINANCIAL EXAMPLE
Two customers both owe ₹30,000/month. One earns ₹40,000/month, the other ₹4,00,000/month. Raw debt tells you almost nothing about risk; debt_to_income tells you everything the raw number was hiding.

CONCEPT 4

Ridge & Lasso Regression

Predicting a continuous number, and taming an old problem: overconfident coefficients.

What it is

Regression predicts a continuous quantity (e.g. expected loan amount) rather than a class. Ridge and Lasso are linear regression with a penalty added that discourages coefficients from growing too large.

Why it exists — the history
~1805
Ordinary Least Squares (OLS) — fitting a straight line by minimising squared error — dates back to Legendre and Gauss, originally for astronomical orbit calculations. It works beautifully until predictors are correlated with each other (multicollinearity) or you have more predictors than data points — then OLS coefficients become wildly unstable, swinging based on tiny data changes.
1970
Hoerl and Kennard introduced Ridge regression: add a penalty on the squared size of coefficients, trading a little bias for a lot less variance.
1996
Robert Tibshirani introduced Lasso ("Least Absolute Shrinkage and Selection Operator"): penalise the absolute size of coefficients instead, which has the extra property of driving unimportant coefficients exactly to zero — automatic feature selection baked into the fitting process.
Alternatives — and why Ridge/Lasso here
OptionTrade-off
Plain OLSUnstable with correlated features or limited data — exactly RR Finance's situation
RidgeStabilises coefficients when predictors are correlated; keeps all features, just shrinks them
LassoSame stabilisation, plus automatic feature selection via exact zeros
Elastic NetBlends Ridge + Lasso penalties — a reasonable default when unsure which one fits better
Tree-based regressors (Random Forest, XGBoost)Capture non-linear interactions Ridge/Lasso cannot, at the cost of interpretability
Neural network regression (Module 2)Most flexible, needs the most data, least interpretable

✓ Use it when

  • Relationship between inputs and target is roughly linear
  • Predictors are correlated with each other (common in finance: income, loan size, and debt all move together)
  • Interpretability and auditability matter

✗ Reach for something else when

  • The true relationship has strong non-linear interactions — check with a tree-based model or Module 2's ANN first
REAL-WORLD FINANCIAL EXAMPLE
Predicting expected loan amount from income, debt and credit history — all three tend to move together, so plain OLS coefficients would be unstable and hard to trust in a report. Ridge keeps the estimate stable; Lasso would additionally tell you which of those correlated fields is actually pulling its weight.

CONCEPT 5

Logistic Regression (Classification)

The baseline every later module in this course gets benchmarked against.

What it is

Logistic regression predicts the probability of a binary outcome (default vs. no default) by passing a linear combination of inputs through the sigmoid function, which squashes any real number into the range (0, 1).

Why it exists — the history
1830s
The logistic (sigmoid) function itself comes from Pierre François Verhulst, modelling population growth that slows as it approaches a carrying capacity — nothing to do with classification originally.
1944 → 1958
Joseph Berkson coined "logit" and championed the logistic function for bioassay in the 1940s; David Cox's 1958 work formalised logistic regression as we use it today. The core motivating problem: plain linear regression can predict probabilities below 0 or above 1, which is nonsensical — logistic regression fixes that by construction.
Alternatives — and why logistic regression as the baseline
OptionTrade-off
Linear regression on a 0/1 targetPredicts impossible probabilities outside [0,1] — a real, avoidable modelling error
Linear Discriminant AnalysisAssumes features are normally distributed within each class — often violated in financial data
Decision Trees / Random Forest / XGBoostCapture non-linear interactions automatically; very common in real production credit scoring, but harder to explain to a regulator than a logistic-regression coefficient table
Support Vector MachinesStrong for smaller, high-dimensional datasets; probability outputs are less natural
Neural network (Module 2)Most flexible, needs the most data and compute, hardest to fully explain
Logistic regressionFast, gives real probabilities, coefficients are directly explainable to a risk committee — the right first thing to try, and the fair baseline every later module in this course is measured against

✓ Use it when

  • You need an interpretable, auditable baseline before anything fancier
  • The relationship between features and the log-odds of the outcome is roughly linear

✗ Reach for something else when

  • Strong feature interactions exist that a single linear boundary cannot represent (Module 2 tests this directly against this exact baseline)
A governance finding, not just a modelling choice
age exists in this dataset and correlates with several fields — but age is a protected attribute under fair-lending regulation (e.g. the U.S. Equal Credit Opportunity Act) in most jurisdictions. The notebook deliberately excludes it from every model's feature list, while keeping it available for a fairness audit in Module 6. This is exactly the kind of decision "explore first, trust second" is meant to surface.
REAL-WORLD FINANCIAL EXAMPLE
A bank's underwriting team needs a probability of default they can explain in one sentence to a risk committee: "for every one-unit increase in debt-to-income, the odds of default increase by X%." That sentence is only easy to say about a logistic regression coefficient — it gets much harder for a random forest or neural network.

CONCEPT 6

Imbalanced Classification + SMOTE

Why a 90%-accurate model can be catching zero of the cases you actually care about.

What it is

When one class (default) is much rarer than the other, a classifier trained naively can achieve high accuracy purely by always predicting the majority class — while being useless at its actual job. SMOTE ("Synthetic Minority Over-sampling Technique") creates synthetic minority-class training examples to counteract this.

Why it exists — the history
2002
Nitesh Chawla and colleagues published the SMOTE paper, motivated directly by domains like fraud and rare-disease detection where the interesting class is naturally scarce. Instead of just duplicating existing minority rows (which teaches a model nothing new and encourages overfitting to those exact points), SMOTE generates new, synthetic points along the line between real minority-class neighbours in feature space.
Alternatives — and why we compare, not just apply SMOTE
OptionTrade-off
SMOTEAdds genuinely new synthetic examples; can occasionally create unrealistic points if classes overlap heavily
class_weight="balanced"Costs one keyword argument, no synthetic data, tells the loss function to penalise minority-class mistakes more — often the better first thing to try
Random undersamplingSimple, but throws away real majority-class data and information
Ensemble methods (Balanced Random Forest, EasyEnsemble)Handle imbalance structurally, at the cost of a more complex model
Reframe as anomaly detection (Lesson 12)When the positive class is extremely rare (well under 1%), "detect the unusual" often outperforms "classify the rare class"

✓ Use SMOTE when

  • Minority class has a reasonable number of examples to interpolate between (not just a handful)
  • class_weight alone hasn't closed the gap

✗ Be careful when

  • Never apply SMOTE before the train/test split — the test set must stay naturally distributed, or your evaluation lies to you
  • Extremely rare classes (fraud at 0.1%) often need a different framing entirely, not just more oversampling
REAL-WORLD FINANCIAL EXAMPLE
A model that predicts "no fraud" for every single transaction can be 99.9% accurate in a dataset where 0.1% of transactions are fraudulent — and catch not one real case. This is exactly why fraud, default, and rare-event financial modelling never reports accuracy alone.

CONCEPT 7

K-Means++

Finding customer groups with no target label to guide you.

What it is

K-Means partitions data into K groups by repeatedly assigning each point to its nearest centroid, then moving each centroid to the average of its assigned points, until the assignments stop changing. It is unsupervised — there is no "correct answer" column to learn from.

Why it exists — the history
1957 → 1982
The core algorithm was developed by Stuart Lloyd at Bell Labs in 1957 for pulse-code modulation (signal processing, not data science at all) — it wasn't formally published until 1982, by which point others had independently rediscovered the same idea for general clustering.
2007
Lloyd's original algorithm picks starting centroids randomly, which can converge to poor, inconsistent groupings depending on luck. David Arthur and Sergei Vassilvitskii introduced K-Means++: a smarter initialisation that spreads out the starting centroids, giving both better and more consistent results — the "++" is what nearly every modern K-Means implementation (including scikit-learn's default) actually uses.
Alternatives — and why K-Means++
OptionTrade-off
K-Means++Fast, scales well, easy to explain to a business audience — but assumes roughly spherical, similar-sized clusters and forces every point into some group
Hierarchical clusteringNo need to pre-specify K, gives a full dendrogram of structure; slower on large data
Gaussian Mixture ModelsSoft/probabilistic cluster membership, handles elliptical clusters; more parameters to estimate
DBSCAN (next lesson)Handles arbitrary shapes and explicit noise — the direct answer to K-Means' biggest weakness

✓ Use it when

  • You expect roughly round, similar-sized groups
  • You have a rough sense of how many groups (K) should exist, or can validate K with a metric like silhouette score

✗ Reach for something else when

  • Cluster shapes are irregular or very different in size/density — try DBSCAN
  • You need every point to belong "softly" to multiple groups — try a Gaussian Mixture Model
Validate K — don't assume it
"Why did we choose this K?" should never be answered with "because a tutorial used 3." The notebook sweeps K=2..7 and picks the value with the best silhouette score — statistical evidence, then combined with business usefulness, before any segmentation gets used operationally.
REAL-WORLD FINANCIAL EXAMPLE
A bank wants to design different relationship-management outreach for different customer segments, but has no pre-existing "segment" label in its data — K-Means discovers behavioural groupings (e.g. high-income/low-debt vs. high-debt/short-history) directly from the numbers.

CONCEPT 8

DBSCAN

Clustering that admits some points just don't belong anywhere.

What it is

DBSCAN ("Density-Based Spatial Clustering of Applications with Noise") groups points that are packed closely together (dense regions), and explicitly labels points in sparse regions as noise rather than forcing them into a cluster.

Why it exists — the history
1996
Introduced by Martin Ester, Hans-Peter Kriegel, Jörg Sander and Xiaowei Xu at KDD 1996 — it later won the conference's "test of time" award for lasting influence. The motivating gap: K-Means forces every point into a cluster and assumes roughly spherical shapes, but real-world data is often irregularly shaped and contains genuine outliers that don't belong to any group at all.
Alternatives — and why DBSCAN here
OptionTrade-off
K-MeansForces every point into a cluster; struggles with non-spherical shapes and varying density
DBSCANHandles arbitrary shapes and gives you an explicit "this doesn't fit anywhere" signal — at the cost of being sensitive to its two parameters (eps, min_samples) and to feature scaling
OPTICSA DBSCAN variant that handles varying density across the dataset better, at higher computational cost
HDBSCANHierarchical density clustering — often the more robust modern default, less parameter-sensitive than plain DBSCAN

✓ Use it when

  • You don't know the number of clusters in advance
  • You explicitly want an "unclassified/noise" bucket
  • Clusters might not be round

✗ Be careful when

  • Density varies a lot across the dataset — a single eps won't fit all regions well
  • You haven't scaled features first — DBSCAN is purely distance-based
The parameter-validation lesson, made concrete
The notebook deliberately shows what happens when you copy eps/min_samples values from a tutorial without checking them against your own data's distance distribution, then walks through validating them properly instead. On RR Finance's real 800-row dataset, DBSCAN mostly finds one dense population plus a handful of true outliers — itself an honest, useful finding: this data does not have several naturally separated behavioural clusters the way a textbook example might.
REAL-WORLD FINANCIAL EXAMPLE
Most customers in a transaction dataset behave similarly (one dense cluster); a small number have genuinely unusual patterns that don't resemble any group — DBSCAN's "noise" label is a natural first-pass triage signal for that second group, distinct from forcing them into an arbitrary segment.

CONCEPT 9

PCA (Principal Component Analysis)

Compressing many correlated numbers into a view a human can actually look at.

What it is

PCA finds new axes — linear combinations of the original features — ordered by how much of the data's variance they capture, so the first two or three "principal components" often summarise most of the interesting structure in a much smaller space.

Why it exists — the history
1901 → 1933
First described by Karl Pearson in 1901 as a way to fit the "best line" through multi-dimensional data, then independently formalised into its modern form by Harold Hotelling in 1933. Long before "dimensionality reduction" was a machine-learning phrase, statisticians needed a principled way to compress many correlated measurements into fewer, uncorrelated ones.
Alternatives — and why PCA
OptionTrade-off
PCAFast, deterministic, mathematically interpretable (each component is a variance-maximising direction) — but strictly linear
Factor AnalysisSimilar goal, but models measurement noise explicitly — more common in psychometrics/econometrics
t-SNE / UMAP (next lesson)Capture non-linear structure PCA misses, at the cost of speed, determinism, and easy interpretation
Autoencoders (deep learning)Learn non-linear compressions directly from data; need much more data and compute than PCA

✓ Use it when

  • Many features are correlated and you want to see the dominant linear structure
  • You need fast, reproducible, interpretable compression before other analysis

✗ Reach for something else when

  • The interesting structure in your data is genuinely non-linear — PCA will miss it entirely
REAL-WORLD FINANCIAL EXAMPLE
An analyst staring at a dozen correlated financial ratios per customer cannot visually inspect a 12-dimensional space — PCA's first two components often let them plot the whole customer base on one 2D chart and immediately see where high-risk and low-risk customers roughly separate.

CONCEPT 10

UMAP

Seeing the non-linear structure PCA is mathematically incapable of showing you.

What it is

UMAP ("Uniform Manifold Approximation and Projection") builds a graph of which points are close to which of their neighbours in the original high-dimensional space, then optimises a low-dimensional layout that tries to preserve those neighbour relationships — capturing non-linear structure PCA's straight-line projections cannot.

Why it exists — the history
2008
t-SNE, by Laurens van der Maaten and Geoffrey Hinton, was the first widely adopted non-linear visualisation technique to gain real traction — but it is slow on large datasets, has no natural way to place new points without recomputing everything, and can distort global distances between clusters.
2018
Leland McInnes and John Healy introduced UMAP, grounded in Riemannian geometry and algebraic topology, as a faster, more scalable successor that better preserves both local and some global structure, and — unlike t-SNE — can transform new points onto an existing embedding.
Alternatives — and why UMAP
OptionTrade-off
PCAFast and interpretable but purely linear
t-SNEGood local structure, but slow at scale and cannot easily embed new points
UMAPFaster than t-SNE, preserves more global structure, supports new-point transforms — the modern default for exploratory non-linear visualisation

✓ Use it when

  • You suspect non-linear structure PCA is flattening away
  • You want an exploratory visual, not a final business conclusion

✗ Be careful when

  • A visually striking UMAP plot is not proof a real business segment exists — treat it as a hypothesis to validate, never a conclusion on its own
REAL-WORLD FINANCIAL EXAMPLE
Complex customer behaviour (spending patterns that shift non-linearly with income bracket, or risk that spikes only above a combined threshold of two features) is exactly the kind of structure a straight-line PCA projection can flatten into invisibility, but a non-linear UMAP embedding can surface for further investigation.
Install note
umap-learn depends on numba, which is sensitive to your NumPy version — a very common classroom install snag. If it fails, try installing in a clean virtual environment before troubleshooting further.

CONCEPT 11 · CYBERSECURITY

Data Poisoning

Attacking the model before it's even trained.

What it is

Data poisoning is an attack on the training process itself: an adversary manipulates some fraction of the training data — here, by flipping labels — so the model learns an incorrect pattern, without ever needing to touch the deployed model or its API.

Why it exists — the history
2004 → 2006
Adversarial machine learning as a formal research area traces to work like "Adversarial Classification" (Dalvi et al., 2004) and "Can Machine Learning Be Secure?" (Barreno et al., 2006), which first systematically asked what happens when a learning system has an active adversary, not just noisy data.
2012
Battista Biggio and colleagues demonstrated a concrete, effective poisoning attack against SVM classifiers, showing the threat was practical, not just theoretical — a foundational result that shaped how the field thinks about training-time security today.
Related attack families — and why we start with label flipping
Attack typeWhat it does
Label flipping (this lesson)Simplest to understand and reproduce — flips y, leaves X untouched — the right starting point before more advanced variants
Clean-label poisoningCorrupts inputs subtly while keeping labels correct, making detection much harder
Backdoor / trojan attacksPlants a hidden trigger pattern the model learns to associate with an attacker-chosen output
Evasion / adversarial examplesAttacks a trained, clean model at inference time instead of during training — this is Module 2's Lesson 10, the direct sequel to this one
The security lesson
The attacker in this lesson never needed access to the model or its API — only the ability to influence training data. That is exactly why dataset access control, provenance, and versioning are security controls, not just data-engineering hygiene.
REAL-WORLD FINANCIAL EXAMPLE
If an internal or third-party data pipeline that feeds a credit model is compromised — deliberately or through a careless bulk-edit script — the model can be quietly retrained on corrupted history without anyone touching the production API at all. The next model refresh silently inherits the damage.

CONCEPT 12

Isolation Forest

Finding the unusual without needing to know what "normal" looks like in advance.

What it is

Isolation Forest detects anomalies with a genuinely different idea from most other methods: instead of modelling what "normal" looks like and measuring distance from it, it repeatedly makes random splits of the feature space and observes that anomalies get isolated in fewer splits than normal points, simply because they're rare and different.

Why it exists — the history
2000
Before Isolation Forest, the dominant approach was density- or distance-based — e.g. Local Outlier Factor (LOF), introduced by Breunig et al. in 2000, which compares a point's local density to its neighbours'. These methods scale poorly (roughly O(n²) distance comparisons) and degrade in high-dimensional spaces.
2008
Fei Tony Liu, Kai Ming Ting and Zhi-Hua Zhou flipped the framing entirely: don't model normal, just try to isolate each point via random partitioning and count how many splits it takes. Anomalies isolate fast; normal points buried in dense regions take many more splits. The result runs in roughly O(n log n), scaling far better to large, high-dimensional financial datasets.
Alternatives — and why Isolation Forest
OptionTrade-off
Local Outlier Factor (LOF)Density-based, intuitive, but slow at scale and weaker in high dimensions
One-Class SVMStrong theoretical grounding, but computationally heavier and sensitive to kernel/parameter choice
Elliptic EnvelopeAssumes data is roughly Gaussian — often violated in real financial data
Isolation ForestFast, scales well, doesn't assume a particular data distribution, and needs no labelled "fraud" examples to train on
Autoencoder reconstruction error (deep learning)Can capture more complex anomaly patterns, needs far more data and compute — an option once the system reaches Module 2/8's territory
Never equate anomaly with fraud
A ₹250,000 transaction may be unusual because the customer bought a car. Isolation Forest gives you a triage signal — where to look first — not a fraud verdict. Fraud determination needs additional evidence, rules, investigation and human judgement.
REAL-WORLD FINANCIAL EXAMPLE
A bank with millions of legitimate records and only a handful of confirmed fraud cases cannot train a normal supervised classifier on "fraud" — there's barely any positive-class data. Isolation Forest needs no fraud labels at all; it just flags what doesn't resemble the bulk of normal activity, for a human analyst to review.

CONCEPT 13

From Individual Checks to a Layered Defence

No single control is enough — and that's the point.

What it is

A layered (or "defence in depth") architecture combines several imperfect controls — schema validation, provenance tracking, anomaly screening, human review, access control — so that no single failure silently compromises the whole system.

Why it exists
Borrowed from classical security engineering
"Defence in depth" predates machine learning entirely — it's a core principle from military and information-security engineering: assume any one layer can fail, and design so that failure doesn't cascade. The modern MLOps/DataOps movement, and artifacts like Datasheets for Datasets (Gebru et al., 2018) and Model Cards (Mitchell et al., 2019), are the ML field's version of the same discipline — treating data and model provenance as first-class, documented, auditable artifacts.
Why layering matters here specifically
Isolation Forest (Lesson 12) is not a complete poisoning defence on its own — a sufficiently subtle, clean-label attack could evade it. Combining anomaly screening with provenance tracking, schema checks, and human review on flagged records is what actually reduces residual risk, because each layer covers a different class of failure.
REAL-WORLD FINANCIAL EXAMPLE
A bank doesn't rely on a single fraud-detection model — it layers real-time rules, ML anomaly scores, human investigator review, and after-the-fact audit trails, precisely because no one layer is trusted to be sufficient by itself.
